# 合成样例数据

这里的二十个人、他们的部门、岗位、序列和公司全部是编的，与任何真实组织无关。
它存在只为一件事：`bun run sync` 不配任何环境变量就能把库填满，
界面、检索和排序立刻有东西可看。

列名就是 `src/corpus/contract.ts` 的契约列，格式见 `src/corpus/sources/csv-dir.ts`。
接自己的数据时把 `TALENT_CSV_DIR` 指向你自己的目录，或者写一个私有适配器。

入职前经历的描述里故意写了几句能抽出能力词和做过的事的话（「从 0 到 1 搭建实时推荐系统」
「使用 Python 和 Spark」「配合风控团队」）。`evals/sample.json` 最后两题问的就是它们：
没配 `EXTRACT_*` 时靠重排模型直接读整段描述，配好之后命中会换成一条能读的短说法
（证据行上写「能力词 Spark」而不是「简历原文」）。这两路为空是打印说明后跳过的结果，不是检索坏了。配好之后入职前的段还会对到
`assignments.csv` 里登记过的序列（比如 E1003 在云枢智能的算法经历对到「技术 · 算法」），
按序列筛人时它们也算数。
