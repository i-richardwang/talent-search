# 合成样例数据

这里的二十九个人、他们的部门、岗位、序列、公司和绩效全部是编的，与任何真实组织无关。
配置好数据库后，未指定数据源的 `bun run sync` 会读取这些样例，
用于体验界面、检索和排序。

列名就是 `src/corpus/contract.ts` 的契约列，格式见 `src/corpus/sources/csv-dir.ts`。
`levels.csv` 是一套编的分档：P7 与 M1 同档、P8 与 M2 同档，用来说明几条职级线可以并进同一档。
学校档有 C9、985、211、QS100 和普通高校；C9 是 985 里更窄的一档（只有 E1008），说「985 毕业」时
要连 C9 一起找，`evals/understand/sample.json` 有一题查的就是它。
接自己的数据时把 `TALENT_CSV_DIR` 指向你自己的目录，或者写一个私有适配器。

入职前经历的描述里故意写了几句能抽出能力词和投入档的话（「从 0 到 1 搭建实时推荐系统」
「使用 Python 和 Spark」「配合风控团队」）。`evals/search/sample.json` 最后两题问的就是它们：
没配 `EXTRACT_*` 时靠重排模型直接读整段描述，配好之后命中会换成一条能读的短说法
（证据行上写「能力词 Spark」）。抽取未配置时能力词为空，解析会报告并跳过。配好之后入职前的段还会对到
`assignments.csv` 里登记过的序列（比如 E1003 在云枢智能的算法经历对到「技术 · 算法」），
按序列筛人时它们也算数。

`streams.csv`、`scales.csv`、`records.csv` 是记录：半年一期的绩效（档从低到高 C、B、B+、A、A+）
和一条高潜池。E1021–E1025 演示按期记录的边界：近三年两次 A、边界外的 A、同一期两条修订、只有两期记录、
没有记录。E1026–E1029 演示限定公司的语义经历：甲辰科技与乙未网络的推荐系统经历，以及只有
一段实习、被「实习不算」否决的人。绩效的期次写死在 2023 年下半年到 2026 年上半年：「近三年」按查询当天往回算，
E1021 与 E1024 的 A 都在 2025 年以后，E1022 那个边界外的 A 在 2023 年上半年，
一年之内跑验收都成立；精确到一天的边界由 `tests/execute.test.ts` 按当天日期造数据检查。
